# Data Governance & Policies
## Champollion Diamond Architecture - Scientific Data Management

This document defines the **immutable laws** governing data flow, provenance, and integrity within the Feldtheorie/Champollion system. These policies ensure scientific validity, reproducibility, and ethical data handling.

---

## Core Axioms

### Policy 1: The Public Domain Axiom

**RULE:** Only publicly verifiable, open-source data may be indexed and processed.

**FORBIDDEN:**
- Personal Identifiable Information (PII)
- Proprietary corporate data
- Passwords, API keys, or credentials
- Copyright-protected internal documents
- Any data that cannot be independently verified through public sources

**VERIFICATION:**
- All data sources must be documented with origin URLs or DOIs
- Internal synthetic data must be clearly marked as such
- When in doubt, exclude rather than include

**CONSEQUENCE:** Violation triggers immediate removal from index and audit trail logging.

---

### Policy 2: Synthetic Distinction Principle

**RULE:** Data generated by models must be clearly distinguished from empirical observations.

**REQUIRED LABELS (in metadata):**
```yaml
origin:
  - empirical      # Real-world measurements/observations
  - synthetic      # Generated by simulation/model
  - theoretical    # Mathematical derivations
  - hybrid         # Combination (requires sub-labels)
```

**ISOLATION:**
- Synthetic data **MUST NOT** overwrite empirical data
- Hybrid datasets require explicit separation of components
- Model outputs stored in dedicated `/synthetic/` subdirectories
- Cross-contamination is a **critical error**

**TRANSPARENCY:**
- Model version, parameters, and random seeds must be logged
- Synthetic data without provenance is rejected
- All transformations must be traceable

---

### Policy 3: Upward Error Propagation

**RULE:** Uncertainty and errors must propagate up the hierarchy.

**MECHANISM:**
1. **Leaf Level:** Each data file includes confidence/error metrics
2. **Branch Level:** Folder indices aggregate child uncertainties
3. **Root Level:** Global index displays consolidated confidence scores

**EXAMPLE:**
```yaml
# File: /data/experiment_001/meta.json
confidence: 0.85
error_margin: 0.12

# File: /data/index.yaml
aggregate_confidence: 0.78  # Propagated from children
low_confidence_items:
  - experiment_001
  - experiment_003
```

**DISPLAY:**
- Indices with `confidence < 0.5` show **WARNING** markers
- Human-readable READMEs include confidence context
- Downstream consumers inherit uncertainty flags

## Data Lifecycle Policies

### Policy 4: Immutable Archive Principle

**RULE:** Raw simulation runs are archived; only aggregated results enter the main index.

**STRUCTURE:**
```
/raw_runs/          ← Full simulation outputs (archived)
  2025-11-23_run001/
  2025-11-23_run002/

/aggregated/        ← Processed results (indexed)
  phase_transitions/
  correlation_functions/
```

**RETENTION:**
- Raw runs: Keep for reproducibility (consider compression after 90 days)
- Aggregated data: Permanent, version-controlled
- Failed runs: Log metadata, discard output (unless debugged)

---

### Policy 5: Provenance Chain Integrity

**RULE:** Every indexed artifact must trace back to its source.

**REQUIRED METADATA:**
```yaml
provenance:
  source_file: "raw_runs/2025-11-23_run001/output.dat"
  processing_script: "scripts/aggregate_phase_data.py"
  script_version: "v2.1.0"
  timestamp: "2025-11-23T14:32:00Z"
  agent: "claude-sonnet-4.5"
```

**VALIDATION:**
- Orphaned files (no provenance) trigger warnings
- Provenance breaks are logged as **CRITICAL**
- Automated scripts must inject their identity

---

### Policy 6: Validation Checkpoints

**RULE:** Automated validation runs before index updates.

**CHECKS:**
1. **Schema Validation:** All JSON/YAML matches defined schemas
2. **Duplicate Detection:** No conflicting IDs or filenames
3. **Governance Scan:** Check for forbidden patterns (emails, IPs, etc.)
4. **Link Integrity:** All referenced files exist

**ACTION:**
- Passing: Index update proceeds
- Failing: Block update, log errors, notify maintainer

## Agent Instructions

### For AI Systems Operating on This Repository:

1. **BEFORE adding data:** Check if it passes Policies 1 & 2
2. **AFTER modifying files:** Run `recursive_diamond_indexer.py`
3. **IF governance violation detected:** Abort and report
4. **WHEN aggregating:** Always check child `confidence` values
5. **READ `folder_context.json` FIRST** before deep-diving into subdirectories

## Summary

These policies form the **contract** between data producers, automated systems, and human consumers. They ensure:

✅ **Scientific Validity:** Clear separation of empirical vs. synthetic
✅ **Reproducibility:** Full provenance chain
✅ **Ethics:** No private/sensitive data
✅ **Transparency:** Confidence levels propagate up
✅ **Automation:** Machines can validate compliance

**Violation = System Integrity Failure.**

This is not optional. This is the foundation.
